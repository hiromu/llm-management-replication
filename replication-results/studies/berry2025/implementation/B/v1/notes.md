# Implementation decisions

Run with R 4.6:

```sh
/opt/homebrew/opt/r/bin/Rscript output/analysis.R --data input/synthetic --out synthetic_out --seed 20261031 --boot 200
```

The standalone script reads only `dataset_1.csv` through `dataset_4.csv` from `--data`. It uses base/recommended R packages and the installed `lme4`, `car`, and `sandwich` packages. It does not need the dictionaries or this directory at runtime. No packages are installed.

- Dataset labels are `D1`–`D4`. Each output quantity uses the exact manifest key and a separate method column. Unspecified methods are `descriptive`, `pearson`, or `cronbach`. Logistic intercepts use R's term name `(Intercept)` and are included in M1–M3; alternatives report the named predictor only.
- Original file rows are numbered starting at 1. For D1, the unit ID is the first original row number for that `part_uid`; deleting that ID deletes every retained row of that person. For D2–D4, the unit ID is the original row number. IDs are never renumbered after filtering. `samples.csv` contains each retained unit once, before quantity-specific complete-case restrictions. D1 units without a valid pair remain available to stacked analyses and leave-one-out deletion.
- D1 pair eligibility requires exactly two rows, one `loyal` and one `control`, and a nonmissing `part_uid`. Each paired outcome then requires both outcome values. Its means and SDs use that same paired sample. `N1.n` counts structurally eligible pairs, while each `P1.*.n` counts outcome-complete pairs. Missing person IDs cannot form pairs and are represented by their own row IDs for retained-row accounting.
- D1 age uses one nonmissing value per retained person, including unpaired persons. Equal repeated ages count once; contradictory nonmissing ages cause the age quantities to fail with a reason. The subgroup variable is participant `gender`, not `gender_person`. Gender/scenario restrictions are applied before pairing for subgroup paired tests; independent tests use all retained eligible rows.
- Numeric conversion uses `as.numeric` after whitespace trimming. Unparseable or non-finite values are missing. Other than manifest sample filters and analysis-specific complete cases, rows are retained. Factor recodes are read from their supplied columns; attention-check expectations use the supplied condition labels and the manifest mappings.
- Means and sums require every item. The global complete-item rule is also applied to `existing`: a deposited composite is used as stored, but is made missing if any constituent item is missing. Supplied reversed D1 items are used directly. The specifically requested accused-item reversal in D2 is computed as `8 - inttrust_accused3`.
- Every mediation model uses a common complete-case sample across all variables in its constituent equations. Thus a parallel model uses the outcome, predictor, and all its mediators; a single-mediator or serial model uses only its own variables. This keeps reported paths, their product, the total and direct effects, and each resample on the same analysis sample. The total effect is an OLS outcome-on-condition regression on that sample. Classical OLS standard errors enter the specified delta formulas; logistic outcome paths use model-based logistic standard errors. Covariance terms are omitted exactly as specified.
- Bootstraps resample rows from that model's complete-case sample, keeping all variables together. The parallel/simultaneous model shares one set of draws across its mediator paths. Each distinct model receives a separate reproducible L'Ecuyer-CMRG stream via `parallel::nextRNGStream`; the requested seed initializes the first stream. Stream starting states are recorded in `session_info.txt`. A failure in one model does not shift another model's random stream. Serial and single-mediator models have their own streams.
- Bootstrap intervals use R quantile type 7. BC uses the exact half-tie rule and ±1.96 without acceleration; an endpoint share of 0 or 1 produces endpoint quantiles, without clipping. `boot_failed` appears once per indirect-effect prefix, with a shared count for paths from a parallel model. Only failed or non-estimable fits are discarded; finite converged fits with warnings are retained. Fewer than two successful resamples makes the bootstrap summaries fail, while the discard count is still reported. Bootstrap fields are omitted at levels where the manifest excludes bootstrapping.
- D1 interaction ANOVA uses observed wrongdoing levels on the complete paired-difference sample. The sum-coded intercept tests the equally weighted average of those scenario means. With only one observed scenario the intercept remains estimable, but the interaction fails. Conflicting wrongdoing codes within a pair cause these ANOVAs to fail. Random-intercept models use all retained complete rows: `outcome ~ cond_recode + (1 | part_uid)` and `outcome ~ cond_recode + (1 | wrongdoing_num / part_uid)`, both REML. Singular but otherwise converged random-effects fits retain fixed-effect Wald results with an explicit message.
- D3 full factorial ANOVAs use sum contrasts and the same full model for all SS types. Type I follows relationship, history, then interaction. The classic eta-squared denominator is corrected total outcome SS; partial eta-squared uses term SS plus full-model residual SS. Cell `n` counts complete outcome values. Pooled contrasts require all four cells and use the outcome-specific full model's MSE and residual degrees of freedom. Student/Welch contrasts and their effect sizes use just the specified two cells. HC3 tests use the full four-cell indicator model.
- Logistic models use unpenalized binomial maximum likelihood, up to 100 iterations. Nonconvergence, rank deficiency, non-finite coefficients, and a single observed outcome class are failures. Converged fits that warn about extreme fitted probabilities remain reported, with warnings; no penalized estimator replaces the requested estimator. Null likelihoods use exactly the corresponding model's complete-case rows. McFadden and Cox–Snell indices follow the manifest formulas. Chi-square uses the observed categories of the supplied transformed predictor, without continuity correction or simulated p values.
- Inferential p values use the requested reference distributions and are not rounded. F and chi-square tests use their usual upper-tail omnibus probabilities; signed t/z tests are two-sided. CSV numeric fields use 17 significant digits for double-precision round trips. SDs use `n - 1`; alpha is raw, unstandardized Cronbach alpha with no automatic item reversal.
- Every requested leave-one-out refit deletes a retained unit before applying the same analysis-specific complete-case rule. Deleting a unit that was not used by that estimand is still reported. D1–D3 use mean composites and D4 uses existing composites. No influence refit bootstraps.
- Errors are retained as failed quantities with explanatory messages; warnings accompany valid results. The script also writes `unmet.md` in `--out` for that invocation. `output/unmet.md` records the final synthetic validation run. Synthetic results are used solely to verify execution, coverage, and numerical consistency, not to draw substantive conclusions.

## Synthetic validation

The final script completed the command above with exit status 0. `synthetic_out` contains `results.csv`, `influence.csv`, `samples.csv`, and `session_info.txt`. An independently assembled manifest inventory matched all 12,710 result key/method/sample/composite combinations exactly, including every key family. All 7,362 required influence rows matched the retained units and estimands. There were no failed result quantities or influence refits; see `output/unmet.md`.

Independent calculations checked OLS paths, delta standard errors, the first parallel model's exact seeded 200-resample bootstrap and BC/percentile intervals, HC3, paired t tests, four-cell pooled contrasts, and logistic coefficients and p values. Additional checks covered every sample filter, duplicate keys, p-value ranges, bootstrap scope and discard counts, empty-sample failure handling, complete-item masking at every composite level, and pair alignment. The schema/coverage check is recorded in `synthetic_out/validation.txt`; execution messages are in `synthetic_out/run.log`. No substantive interpretation of the synthetic values was made.
