1. Section 2 requires declared missing codes to be applied per variable. The code uses raw V8 and V17 for controls and routing, raw V43 for industry lookup, and raw WEIGHT with only a positivity check, bypassing their metadata declarations (`code/paperk7/coding.py:270`, `code/paperk7/coding.py:306-319`, `code/paperk7/coding.py:423-442`, `code/paperk7/coding.py:503`, `code/paperk7/coding.py:515-516`). In particular, a positive declared-missing WEIGHT remains eligible for WLS, contrary to sections 2 and 5.
2. Section 4.3 excludes STAFF codes 995-999 under L0/L1 and retains only 995 as an exception under L2. Code 996 is absent from the explicit exclusions and is logged as a count unless independently declared missing in the metadata (`code/paperk7/coding.py:136-155`).
3. Sections 2 and 4.3 require staff_coding L2 to retain 995 despite declared missing codes. The `keep=[995]` exception removes 995 only from individual missing values; a declared missing range containing 995 still masks it (`code/paperk7/coding.py:65-69`, `code/paperk7/coding.py:139-140`). Likewise, the explicit recodes of V157 = 99996 to 100000 and V261 = 96 to 100 under sections 4.4 and 4.11 occur only after metadata masking, so those recodes are lost if the top codes are declared missing (`code/paperk7/coding.py:221-222`, `code/paperk7/coding.py:288-297`).
4. Sections 4.3 and 4.9 require missing STAFF CORE items to be ineligible for the system-missing V79 copy and to permit the manager's GSS fallback. Under item_rule L2 with staff_coding L0, a CORE count of 0 remains nonmissing during copying: it can overwrite a valid GSS item and is selected instead of a valid GSS fallback for the manager. It becomes missing only during the later log transformation (`code/paperk7/coding.py:130-149`, `code/paperk7/coding.py:188-195`, `code/paperk7/coding.py:208-210`).
5. Section 4.10 requires the L1/L2 reference analysis sample to be determined before, and independently of, standardization. The code determines it using L0 standardized indices, then recomputes and replaces sample membership after reference-sample standardization; when membership changes, the scores retain moments from the earlier sample (`code/paperk7/pipeline.py:95-113`, `code/paperk7/pipeline.py:122-134`).
6. Section 4.12 requires SUBSID = 0 whenever V17 == 2 under subsidiary L1/L2. When V21 also satisfies the positive condition, both Boolean masks are true and the assignment of 1 overwrites 0, producing SUBSID = 1 (`code/paperk7/coding.py:119-124`, `code/paperk7/coding.py:314-319`).
7. Section 6 requires HC3 SE, t, and tail probabilities for every coefficient. The implementation replaces all HC3 statistics with missing values whenever any observation has `1 - h <= 1e-8`, including positive denominators for which HC3 is defined (`code/paperk7/regression.py:114-130`), while reporting the model as `ok` (`code/paperk7/pipeline.py:278-284`).
8. Sections 4.14 and 7 require collinear industry dummies to be dropped in an estimation sample. Influence refits start from the original design including previously dropped dummies and attempt fitting before removing collinear dummies. Because fitting checks `n <= k` before rank, a deletion can be recorded as having no residual degrees of freedom without dropping collinear dummies that would permit estimation (`code/paperk7/pipeline.py:285-286`, `code/paperk7/pipeline.py:328-358`, `code/paperk7/regression.py:83-98`).
9. Section 7 requires a refit for every record in each specified model's estimation sample and retention of every deletion, including failures. When an origin model fails, its design and record identifiers are discarded; influence processing emits only one failure row per term with missing deleted_V1 and skips all individual deletions (`code/paperk7/pipeline.py:289-294`, `code/paperk7/pipeline.py:380-389`).
10. Sections 4.14, 6, and 8 require dropped industry columns to be recorded. If fitting fails after dummy removal, the removal information is lost and the failed model's dropped_columns remains `NA`, even though columns were dropped (`code/paperk7/pipeline.py:177-181`, `code/paperk7/pipeline.py:217-226`, `code/paperk7/pipeline.py:289-293`).
11. Section 8 requires failures in run_info.json. Individual influence-refit failures are written to influence.csv but never added to the failures list returned by run_influence, so run_info.json omits them (`code/paperk7/pipeline.py:365-371`, `code/paperk7/pipeline.py:375-391`, `code/run_grid.py:112-114`, `code/run_grid.py:153-154`).
12. Section 8 requires `NA` for missing values. Missing numerical values in run_info.json are converted to `None` and serialized as JSON `null` (`code/run_grid.py:124-133`, `code/run_grid.py:164-169`).
13. Section 9 specifies hierarchy_log10 as the log10 of the L0 value, which section 4.11 defines as ln of the recoded hierarchy count. The check instead computes log10 directly from the recoded count (`code/paperk7/coding.py:287-293`).
