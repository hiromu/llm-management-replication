1. Section 2 requires applying declared missing codes per variable. Industry construction passes raw V43 directly to the crosswalk lookup, bypassing metadata missing-code handling; a declared-missing numeric code absent from the crosswalk becomes `UNCL` under industry L0 instead of missing (`code/k7_lib.R:336`, `code/k7_lib.R:122-135`).
2. Sections 4.3 and 4.9 require CORE-item validity for the system-missing V79 copy condition and a GSS fallback when the CORE item is missing. The copy helpers check only `is.na()` before STAFF-specific exclusions are applied. Under item_rule L2 with staff_coding L0, CORE V62 = 0 is therefore treated as valid: it can overwrite a valid V97 and prevent the manager item from using a valid V97 fallback, although section 4.3 makes 0 missing (`code/k7_lib.R:167-169`, `code/k7_lib.R:177-188`, `code/k7_lib.R:192-204`).
3. Section 4.12 specifies SUBSID L0 as 1 when V17 == 1 and 0 otherwise. The implementation instead assigns missing when V17 is system-missing (`code/k7_lib.R:277-278`).
4. Section 4.14 requires dropping collinear industry dummies in the estimation sample. The implementation rejects a model when N is no greater than the column count before checking collinearity, so it can fail without dropping collinear dummies even when dropping them would leave positive residual degrees of freedom (`code/k7_lib.R:475-482`).
5. Sections 4.13 and 5 specify the controls, HRM terms, and interactions to include; section 4.14 authorizes dropping industry dummies. The implementation also drops all-zero or collinear HRM, interaction, and control columns, reports the reduced model as successful, and omits those coefficients from the output (`code/k7_lib.R:473-481`, `code/k7_lib.R:508-517`).
6. Section 5 specifies nested-test numerator degrees of freedom as the number of added terms: six for an HRM block and three for an interaction block. The implementation uses the difference between parameter counts after column dropping, which can differ from those required counts (`code/k7_lib.R:524-529`).
7. Sections 6 and 7 require recording dropped columns and flagging dummies made all zero by a deletion. If a fit drops columns and subsequently fails, the drop information is lost: it is accumulated in a local variable but copied into the returned result only on success, while failed influence rows record only the error (`code/k7_lib.R:466-479`, `code/k7_lib.R:514-519`, `code/k7_lib.R:664-667`).
8. Section 7 requires one refit per estimation-sample record and retention of every deletion, including failures. When the original model fails, the implementation skips all deletion refits and returns a single failure row with deleted_V1 missing, even though the estimation-sample identifiers are attached to the failed fit (`code/k7_lib.R:592-593`, `code/k7_lib.R:641-646`).
9. Section 8 requires run_info.json to list failures. A restricted-model refit failure during a nested test is replaced by an all-missing test result without retaining its reason or adding it to the failures list (`code/k7_lib.R:620-624`, `code/run_grid.R:79-80`, `code/run_grid.R:132`).
10. Section 8 requires `NA` for missing values. The JSON writer explicitly serializes missing values as `null`, including missing identifiers in failure records (`code/run_grid.R:67`, `code/run_grid.R:140`).
11. Section 9 specifies CHK_hierarchy_log10 as log10 of the L0 VHIER value, which section 4.11 defines as the natural logarithm of the recoded hierarchy count. The implementation instead computes log10 of the recoded count itself (`code/k7_lib.R:262`, `code/k7_lib.R:266-268`).
